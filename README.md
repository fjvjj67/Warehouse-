# خريطة المخزن 3D

ملف واحد (`index.html`) يعرض مخزن AZAWI بشكل ثلاثي الأبعاد: 17 غرفة + 3 ممرات، بحث بالاسم أو SKU أو الباركود، وتحديد الرف والمستوى على الخريطة.

## التشغيل
الرابط: https://fjvjj67.github.io/Warehouse-/ (GitHub Pages من فرع `main`). محلياً: افتح `index.html` بالمتصفح (يحتاج إنترنت لتحميل three.js).

## المزايا
- بحث ذكي (يتجاهل التشكيل والهمزات) + مسح باركود
- عرض فقط: الكميات والمواقع مصدرها دفترة، والتحديث يصير بـ `tools/update_catalog.py`
- حالة المخزون: متوفر / منخفض (≤10) / نافد، وملخص بالأسفل
- عرض بقية المنتجات الموجودة على نفس الرف
- بيانات حقيقية: 119 منتج من نسخة POS الاحتياطية (14-10-2026)، والمنتجات بكمية 0 متروكة
- المنتج ممكن يكون على أكثر من رف (مثل `R3-C6+C7+D2+D3`) وتتلون كل رفوفه
- تصدير CSV بنفس أعمدة ملف الاستيراد

## تحديث المنتجات من دفترة
`python3 tools/update_catalog.py Backup_Products_....xlsx` يدخل النسخة الاحتياطية داخل `index.html` (يترك الكمية 0 ويبلّغ عن المواقع غير الموجودة)، وبعدها تُنشر الصفحة. الصفحة مفتوحة بدون كلمة مرور.
للتجربة بدون تعديل: أضف `--dry-run`.

## ملصقات الرفوف
`labels/R3-labels.pdf`: ملصق لكل رف ولكل مستوى (كود + باركود)، ورق A4 بـ 24 ملصق (70×37 ملم).
مسح باركود الملصق أو كتابة الكود (مثل `R3-A-3`) بحقل البحث يفتح المستوى على الخريطة.
لغرف ثانية: `python3 tools/make_labels.py R4 R5` أو `python3 tools/make_labels.py all`.

## خطوات التطوير المقترحة
1. نقل `PRODUCTS` إلى ملف `products.json` أو قاعدة بيانات (Supabase) وربطه بنظام الجرد/POS.
3. حد أدنى مستقل لكل منتج بدل الرقم الثابت 10.
4. سجل حركة (من نقل المنتج ومتى) وتصنيف ABC لتقريب الأسرع مبيعاً من الباب.
